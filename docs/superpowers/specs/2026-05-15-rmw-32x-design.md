# RMW 32× 확장 (col-parallel) Design

**Date:** 2026-05-15
**Status:** Design — brainstorming 결과 정리, implementation plan 직전 단계
**Scope:** RMW 1 instance → 32 instance (col-parallel). SRAM wrapper 를 single-port mux 형에서 per-bank 독립 port 노출형으로 교체. TB 의 capture/drain 을 32 stream 으로 분리. **Feasibility 검증** 이 목적이고, throughput / area / timing closure 는 non-goal.

이 spec 의 상위 컨텍스트는 `docs/superpowers/specs/2026-05-14-integration-design.md` (시스템 통합 spec) 및 `CLAUDE.md` "Settled — with re-visit triggers" 표. 본 spec 은 그 표의 **"RMW instance 수"** 항목 재검토 트리거 (throughput / area / sim time) 를 발동시킨 후속 단계.

---

## 1. 목적 / Goals / Non-goals

### Goals
1. RMW 를 col-parallel 로 32 instance 확장한 데이터패스가 9 정밀도 조합 (A∈{2,4,8} × B∈{2,4,8}) 전부에서 기존 1-RMW 결과와 **bit-exact 일치** 함을 확인 — 즉 MXP_Tools golden 과의 회귀가 깨지지 않음.
2. `sram_1rw_banked_mp.v` (per-bank port 노출 wrapper) 가 단위 레벨에서 동작함을 확인.
3. col j → bank j 매핑이 모든 mode 에서 **충돌 0** 임을 RTL + Python 양쪽에서 표현하고 round-trip 검증.
4. 1-RMW 대비 sim time 단축을 실측 (목표값 없음, "단축되면 OK" 게이트).

### Non-goals (명시)
- Throughput 의 이론 한계 분석 — 단순히 sim time 단축 사실만 기록.
- Timing closure / 합성 / area 추정.
- Synthesizable arbiter / controller — wrapper 는 여전히 pure structural, TB 가 매 cycle bank 마다 R/W signal driving.
- Real-time drain (DRIVE 와 DRAIN 동시 진행) — 별도 spec 으로 deferred.
- Multi-port SRAM cell (1RW 그대로 두고 bank 노출로 bandwidth 확보).
- Loop order / 워크로드 / SRAM 구조의 최종 결정 — 잠정값 그대로.

### 잠정값 유지 (재검토는 별도 phase)
- Loop order: K-outermost (`n_t → k_t → m_t → o`).
- 워크로드: M=K=N=128.
- SRAM PIPELINE: 0.
- RMW latency (L_CONV, L_ADD) = (2, 3).
- 매핑: row-major flat → bank = flat % NB (= INTERLEAVED 의미는 호출자가 결정).

## 2. 시스템 wiring (current → target)

### 현재 (1-RMW)
```
GEMM ──► RMW (단일) ──► sram_1rw_banked (16 bank, mux 형 단일 A/D/Q)
            ▲              │
            └──── Q ◄──────┘
```
- TB 가 `out_fire[c]` 32 비트를 모니터링 → 단일 FIFO (`fifo_int/scale/addr`) 에 캡처.
- DRIVE 끝난 뒤 DRAIN 단계에서 FIFO 를 순차로 1 RMW 통과.

### 목표 (32-RMW, col-parallel)
```
                                                    bank[0] ─► Q[0] ─► RMW[0].in_SRAM
GEMM ──► (per-col capture in TB)                                            │
         out_fire[c], out_accumulate[60c+:60],                              ▼
         out_scale[36c+:36] ── TB FIFO[c] ─► RMW[c].in_GEMM, .scale ──► out_RMW[c]
                                                                            │
                                                                            ▼
                                                    bank[c] (1RW leaf, indep. port)
                                                            (write-back)

(c = 0..31 동일 wiring, 32 stream 독립)
```

### `gemm_sram_top.v` (수정)
- `RMW` 1 개 → `RMW[32]` (generate for).
- `sram_1rw_banked` 단일 인스턴스 → `sram_1rw_banked_mp` 단일 인스턴스, NUM_BANKS=32, BANK_DEPTH=1024.
- 두 줄 구조적 wiring 의 32-fold 버전:
  - bank[c].Q → RMW[c].in_SRAM (per-col hardwire)
  - mux(sram_D_use_zero, 0, RMW[c].out_RMW) → bank[c].D (per-col)
- 포트: GEMM 자극과 SRAM/RMW 제어가 모두 32 배로 늘어남. TB 가 직접 driving.

## 3. 새 wrapper — `sram_1rw_banked_mp.v`

기존 `sram_1rw_banked.v` (single-port mux 형) 는 deprecate 안 하고 공존. 새 파일.

### 포트
```verilog
module sram_1rw_banked_mp #(
    parameter DATA_WIDTH = 32,
    parameter NUM_BANKS  = 32,
    parameter BANK_DEPTH = 1024,
    parameter PIPELINE   = 0
)(
    input  wire                                       CLK,
    input  wire [NUM_BANKS-1:0]                       CEB,    // per-bank, active-low
    input  wire [NUM_BANKS-1:0]                       WEB,    // per-bank, active-low
    input  wire [NUM_BANKS*$clog2(BANK_DEPTH)-1:0]    A,      // flat slice
    input  wire [NUM_BANKS*DATA_WIDTH-1:0]            D,      // flat slice
    input  wire [NUM_BANKS*DATA_WIDTH-1:0]            WMASK,  // flat slice
    output wire [NUM_BANKS*DATA_WIDTH-1:0]            Q       // flat slice
);
```

- `BANK_STRATEGY` 파라미터 **삭제** — 각 bank port 가 독립이므로 wrapper 레벨에서 INTERLEAVED/SEQUENTIAL 구분 무의미. 매핑은 호출자 (TB / MXP_Tools) 책임.
- `NUM_BANKS` 2의 거듭제곱 sanity check (기존 wrapper 패턴 재사용).
- `generate for (i = 0; i < NUM_BANKS; i = i + 1)` 로 leaf `sram_1rw` 32 개 instantiate. 각 leaf 의 모든 입출력은 자기 bus slice (`A[i*AW +: AW]` 등).
- Verilog-2001 호환 유지 (sram repo 컨벤션) — packed array 안 씀, flat bus 만.

### 단위 회귀
- `tb/sram_1rw_banked_mp_tb.v` — 한글 헤더 (검증 목적 / 검증 내용 / 동작 의도) 필수.
- 검증 시나리오: bank 마다 다른 데이터 동시 write → 동시 read → 각 bank Q 가 자기 데이터 일치.
- `sim/run_sram_mp.sh` — XSim 배치 회귀.

## 4. Bank addressing — col j → bank j (conflict-free 증명)

`flat = m*N + n_pos`, N=128, NB=32. `128 % 32 = 0` 이므로 `bank = n_pos % 32`.

| Mode | n_pos | bank | word (bank j 내부) |
|---|---|---|---|
| A8 | `n_t*32 + j` | `j` | `m*4 + n_t` |
| A4 top | `n_pair*64 + 32 + j` | `j` | `m*4 + n_pair*2 + 1` |
| A4 bot | `n_pair*64 + j` | `j` | `m*4 + n_pair*2` |
| A2 lane 0 (n=96+j) | `96 + j` | `j` | `m*4 + 3` |
| A2 lane 1 (n=64+j) | `64 + j` | `j` | `m*4 + 2` |
| A2 lane 2 (n=32+j) | `32 + j` | `j` | `m*4 + 1` |
| A2 lane 3 (n=0+j)  | `j` | `j` | `m*4 + 0` |

**결과**: 모든 mode 의 모든 lane 에서 `bank = j` (col 번호). col j 의 RMW 가 오직 자기 bank j 만 건드림. **충돌 0**.

bank j 내부 word range: `m ∈ [0..127]`, `n_t/n_pair/lane ∈ [0..3]` → `word ∈ [0..511]` 사용. 나머지 (512..1023) 는 zero-prime 후 미사용.

→ **BANK_DEPTH = 1024** (workload 512 + 2× headroom). 추후 워크로드 변경 시 재합성/파라미터 sweep.

## 5. TB 변경 — `gemm_sram_top_tb.v`

### Capture (DRIVE 단계)
- 단일 FIFO 3 종 → `fifo_int[32]`, `fifo_scale[32]`, `fifo_addr[32]` 로 분리.
- `out_fire[c]` rising 감지 로직과 mode 별 lane 디코딩 (A8: 1, A4: 2, A2: 4 entry push) 은 기존 그대로. push 위치만 `fifo_*[c]` 로 분기.

### DRAIN (32 stream 병렬)
```
generate for (c = 0..31): per-col always block (state machine)
  state[c] ∈ {IDLE, READ, WAIT_R, DRIVE_RMW, WAIT_RMW, WRITE, DONE}
  pop (int, scale, addr) from fifo[c]
  bank_idx = addr & 0x1F           (= c, assert)
  word_addr = addr >> 5
  READ: bank[c] CEB=0, WEB=1, A=word_addr        — 1 cycle
  WAIT_R: leaf PIPELINE=0 이라 1 cycle 후 Q 유효
  DRIVE_RMW: RMW[c].in_GEMM = int, .scale = scale
  WAIT_RMW: L_CONV + L_ADD = 5 cycle
  WRITE: bank[c] CEB=0, WEB=0, A=word_addr, D=RMW[c].out_RMW, WMASK=32'hFFFFFFFF
  ...
end
```

- 32 stream 의 bank port 가 독립이므로 cycle-level 간섭 없음.
- 동기화 게이트: 모든 stream FIFO empty + 마지막 write-back settle 후 DUMP 진입.
- 기존 TAIL_CYC / POST_TAIL / PRIME_CYC 상수 유지 (capture window 의미는 동일).

### INIT (zero-prime)
- 기존: 16384 word × 1 RMW dispatch = 16384 cycle.
- 신규: 32 bank port 동시 zero-write, 1024 cycle. (32 bank × 1024 depth = 32768 word 까지 가능하나 1024 cycle 안에 한 줄씩 32 개 동시 write.)

### 한글 주석
- 새/수정 TB 의 헤더에 **검증 목적 / 검증 내용 / 동작 의도** 한글로 명시 (메모리 `feedback_comments_korean.md` 룰).

### 검증 가드 (TB 안에서 sim-time assert)
1. capture 직후: `assert((addr & 0x1F) == c)` — col-to-bank 매핑 = spec 표 § 4 와 일치.
2. dump 직후: bank 마다 word ≥ 512 영역이 0 으로 남아 있는지 spot-check (zero-prime 그대로).
