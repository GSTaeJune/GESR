Mixed-Precision GEMM 시뮬레이션 튜토리얼

본 튜토리얼은 gemm_sram 프로젝트에서 mixed-precision (per-(M-row, K-block) W_PREC 혼용) GEMM 검증을 처음 돌리는 분을 위한 end-to-end 가이드입니다. 데이터 생성 → 시뮬레이션 → 비교까지 한 cycle.

전제: Vivado 2024.1 xsim CLI (PATH 등록), Python 3.10+, numpy, matplotlib. Repo root = C:/Users/ptj72/Desktop/Desktop/00project/gemm_sram.

1. Quick start — 한 줄 실행

random mixed-W 케이스 (default) end-to-end:

bash sim/run_mixed_one.sh 8
# A_PREC=8, random per-(M, K-block) W_PREC ∈ {2,4,8}
# 약 1.5분 (xsim sim + compare)

성공 시 마지막 줄:

pair                   max          rmse      mean_abs      snr_dB    n_diff
hw_sw            0.000e+00     0.000e+00     0.000e+00        inf         0
mixed_A8: PASS
핵심: hw_sw 의 n_diff = 0 이면 bit-exact PASS. sw_fp32 / hw_fp32 의 n_diff 는 quantization noise (정상).

3. Precision map — 어디서 보고 어떻게 읽나

3.1 파일 위치

파일내용
work/<LABEL>/precision_map.png (M=128) × (K-block=4) 의 W_PREC 색지도. 한눈에 분포 확인용.
work/<LABEL>/precision_map.txt 같은 데이터의 숫자 dump. diff / grep 으로 비교 가능.

3.2 색 의미 (PNG)

W=2 (INT2, 1-bit weight × cnt=1)
W=4 (INT4, cnt=3)
W=8 (INT8, cnt=7)

3.3 TXT 포맷

# precision_map  A_PREC=8  seed=0
# rows = M=0..127, cols = K-block 0..3
# values: 2 / 4 / 8 (W_PREC per block)
8442    # M=0: K-block 0=W8, 1=W4, 2=W4, 3=W2
2222    # M=1: 모든 K-block W2
2848    # M=2 ...
...
왜 (M, K_T) 매트릭스인가: SA 의 row=K, col=N, cycle=M 진행. 한 cycle 의 32-bit weight 는 같은 K-block 의 32 K-element 의 bit (같은 W_PREC). M 진행마다 W_PREC 갱신 가능 → (M-row, K-block) 단위 W mix. 자세한 매핑은 precision_modes_protocol.md §1, CLAUDE.md "MXP control surface" 참조.

5. 변형 — 환경변수 override

sim/gen_mixed.py 의 W_PREC map 생성을 시나리오에 따라 바꿀 수 있습니다 (디버그/isolation 용).

시나리오명령의미
random (default) bash sim/run_mixed_one.sh 8 (M=128, K_T=4) 전부 random W_PREC ∈ {2,4,8}
uniform W=8 MIXED_W_UNIFORM=8 bash sim/run_mixed_one.sh 8 모든 block W=8 (9-mode A8W8 과 동등)
uniform W=4 MIXED_W_UNIFORM=4 bash sim/run_mixed_one.sh 8 모든 block W=4
K-tile granular MIXED_W_K_TILE=8,4,2,8 bash sim/run_mixed_one.sh 8 K-block 단위 mix (모든 M 동일 pattern). 예: 4 block = [W8, W4, W2, W8]
isolation 순서 권장: uniform → K-tile granular → random 순서로 확장. RTL/TB 변경 후 회귀 확인 시 이 순서로 fail 좁히기.

6. 결과 검증 — mxp_tools compare

6.1 자동 호출 (sweep script 안에서)

cd MXP_Tools && python -m mxp_tools compare \
    --ref ../work/mixed_A8/sw_ref/C_sw_mixed.npz \

    --layout interleaved_row_major_32bank

6.2 출력 해석

pair                   max          rmse      mean_abs      snr_dB    n_diff
hw_sw            0.000e+00     0.000e+00     0.000e+00        inf         0
sw_fp32          2.418e+01     3.470e+00     2.489e+00      10.21     16384
hw_fp32          2.418e+01     3.470e+00     2.489e+00      10.21     16384
row대상합격 기준
hw_sw HW (xsim) vs SW golden (mixed quant) n_diff = 0 (bit-exact)
sw_fp32 SW golden vs FP32 truth (unquantized) n_diff > 0 정상 (quantization noise)
hw_fp32 HW vs FP32 truth hw_sw=0 이면 sw_fp32 와 동일해야 함
주의 (현재 한계): mxp_tools.compare 가 mismatch 일 때 stats 만 print 하고 sys.exit(1) 안 함 → script 의 set -e 걸려도 false-positive "PASS" 가능. n_diff 값을 사람 눈으로 확인 필수. (개선 작업 별도 todo: n_nonzero_diff > 0 시 exit 1.)

8. RTL dataflow 핵심 (디버그 시 참조)

mixed-W 디버그 시 잘못된 결론으로 점프하지 않으려면 cycle 단위 dataflow 를 정확히 알아야 합니다. 핵심 5 가지:

8.1 SA 차원 매핑 — row=K, col=N, cycle=M (가장 자주 헷갈림)

SA 축행렬 차원
row (in_a[r], in_b[r])K-axis (PE_feeder 대각선, K=r 의 weight 가 N-col 방향 전파)
col (Accumulator_Col[c])N-axis (N-col c 의 dot product)
cycle (W_CYC 단위)M-axis 진행

8.2 in_Wcontrol cadence (mixed-W 핵심)

drive_w_cyc[k] = 18 + Σ_{j=0..k-1} W[j]   # cum_W_exclusive

m_in=k 의 MAC 시작 cycle 에 in_Wcontrol <= W[k] 드라이브. m_in=0 의 cycle 18, m_in=1 의 cycle 18+W[0], ...

8.3 in_scale_weight cadence (fire 캡처 시점 정합)

drive_cyc[k] = 18 + A_FIRE_DELAY + Σ_{j=0..k} W[j]   # cum_W_inclusive

A_FIRE_DELAY: A8=2, A4=1, A2=0 (Accumulator_Col 의 fire chain 깊이).

8.4 fire chain → out_scale 캡처 timing (A=8 예시)

cycle  signal
─────  ───────────────────────────────────────
  18   in_Wcontrol = W[0],  MAC 시작 (cnt 0)
  25   cnt = 7,  fire_cycle = high
  26   acc_fire = 1,  cnt = 0  (m_in=1 MAC 시작, in_Wcontrol = W[1])
  27   fire_q1 = 1
  28   fire_q2 = 1   ← comb_s 가 이 cycle 의 값으로 계산
  29   out_scale 캡처 (posedge 29 에서 comb_s(28) latched)
       ↑ in_Wcontrol(28) = W[1] (이미 다음 m_in 값) ← WRONG impl_w

8.5 impl_w 파이프라인 (2026-05-18 RTL fix)

해결: impl_w 를 fire chain 깊이 + 1 만큼 지연 (Accumulator_Col 의 새 reg chain):

reg [3:0] impl_w_q1, impl_w_q2, impl_w_q3;
wire [3:0] impl_w_eff = is_A8 ? impl_w_q3 :
                        is_A4 ? impl_w_q2 :
                        is_A2 ? impl_w_q1 : impl_w;
// always block:
impl_w_q1 <= impl_w;
impl_w_q2 <= impl_w_q1;
impl_w_q3 <= impl_w_q2;
uniform W 시 q1=q2=q3=impl_w 라 9-mode 회귀 영향 없음. 자세한 설명은 precision_modes_protocol.md §7 (v1.1 추가분) 참조.

9. 트러블슈팅

9.1 xsim "Failed to launch child process (child exe not found)"

이전 xsim instance 잔여물. build dir 정리:

rm -rf sim/build/mixed_A8 && bash sim/run_mixed_one.sh 8

9.2 compare 가 PASS 인데 n_diff > 0

compare 의 fail-gate 미구현 (§6.2 주의). 출력에서 hw_sw n_diff 직접 확인.

9.3 mismatch 발생 → 어디부터 의심?

  1. Python sanity: cd MXP_Tools && python -m pytest tests/ -q (45 cases, 0.3 s) PASS 인지.
  2. emit/golden 분리: gen_mixed.py 의 hex emit (_emit_a_input_bs) 와 golden (compute_golden_mixed) 이 uniform 케이스에서 MXP_Tools 의 hwio.emit_a_input_bs + gemm.mxint_gemm_golden 과 byte-identical 한지.
  3. isolation 분리: random fail 시 MIXED_W_UNIFORM=8 로 uniform 돌려보기.
    • uniform PASS → mismatch 는 mixed-pattern 특화 (W cadence, impl_w timing, chain skew).
    • uniform 도 fail → 더 기본 (emit / driving sequence / RTL build).
  4. cycle 도식화: §8 의 fire chain ↔ in_Wcontrol cadence ↔ comb_s 캡처 cycle 을 손으로 그려가며 mismatch 위치 추적.

9.4 9-mode regression fail (RTL 변경 후)

uniform 케이스 깨졌으면 RTL 변경이 회귀 유발. 변경분 revert 또는 mode-별 분기 (예: impl_w_eff 처럼 mode-aware) 으로 재설계.
